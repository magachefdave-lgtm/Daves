# EM 평가 현황 대시보드 v0.7.0

Wafer level 신뢰성 평가 중 EM(시료를 Ceramic PKG 에 본딩, Micro oven 설비) 진행 현황을 사내망 브라우저로 보는 도구입니다.
Micro oven 설비마다 Oven 이 5~24대 있고, Oven 1대에 DUT 보드 1장(시료 16개)이 들어갑니다.
DUT `8/8` = 진행 보드 8 / 계획 보드 8 (시료 8×16개 모두 진행). Tester 칸은 작업자 이니셜입니다.
기존 EM `.txt` DB(쉼표 구분, 16/17컬럼)를 **읽기만** 하며, 원본 파일을 절대 쓰지 않습니다.
작업자 입력 칸(Sdm_no, Test_in, Test_out, Wafer_in, PKG_Line, PKG_in, 비고, **설비**, **Oven(DUT)**)은 현황 표에서 바로 입력하고,
그 값은 서버 PC 의 `data/overlay.db`(SQLite)에 따로 저장되어 화면에서 원본 위에 덮어 보입니다.
행 추가·삭제·되살리기도 같은 `overlay.db` 에 저장됩니다. 동시 사용 인원 2~10명 기준으로 만들고 시험했습니다.

## 구조

| 경로 | 역할 |

## 판정 규칙 (rules.js 머리말이 원본)

- 단계: Test_out 있음 → 평가완료 / Test_in → EM 진행중 / PKG_in → Test 대기 / Wafer_in 또는 PKG_Line → PKG 진행 / 그 외 입고대기 (v1.2 규칙 그대로)
- 경과일 = 기준일 − 지금 단계에 도착한 날. PKG 진행은 PKG_Line(없으면 Wafer_in), Test 대기는 PKG_in, 진행중은 Test_in. 입고대기·완료·날짜 오류는 경과일을 내지 않음. **지연 기준일·지연 판정은 쓰지 않습니다** (요청에 따라 v0.5.0 에서 뺌).
- 데이터 확인 필요: 날짜 형식 오류, 미래 날짜, 날짜 순서 역전, Test_in 없이 Test_out, PKG_in 없이 Test_in, 수량 ≠ DUT 보드 × 16, 중복 행 키
- Oven 사용 = **설비** 칸별 EM 진행중 건의 진행 보드 수 합 (DUT "8/8" 의 앞 숫자, 보드 1장 = Oven 1대). `[equipment_ovens]` 에 설비별 전체 대수(5~24)를 적으면 빈 Oven 수를 냅니다. 설비를 입력하지 않은 진행 건은 "설비 미입력" 으로 모아 보여 줍니다.
- **Oven(DUT)** 칸 = 그 평가가 들어간 Oven 번호. `1|2|3`, `1-8`, `1~4|7`, `1 2 3` 모두 받습니다(쉼표는 쓰지 마세요). "Oven 사용" 화면에 설비마다 Oven 칸이 번호별로 그려지고, 어느 List 가 쓰는지 보입니다.
- 데이터 확인에 추가: Oven 번호 형식 오류, 진행중인데 입력한 Oven 수 ≠ 진행 보드 수, 같은 설비의 같은 Oven 을 진행중 두 건이 씀(겹침).
- **설비**, **Oven(DUT)** 칸은 원본 .txt 에 없는 칸입니다. `overlay.db` 에만 저장되고, "TXT 내보내기" 는 원본과 같은 17컬럼이라 두 칸이 빠집니다(엑셀 .csv 에는 들어감).

## 작업자 입력 규칙

- 행 식별 키 = 기본 `Test` + `List_no`. config.ini `[data] row_key = Test,List_no` 로 바꿀 수 있습니다(예: `Test,List_no,Lot_ID`). 작업자 입력 칸은 키로 쓸 수 없습니다.
- 키가 두 줄 이상이거나 키 칸(Test 제외)이 비어 있으면 그 행은 입력·삭제를 막습니다.
- row_key 를 바꾸고 서버를 다시 켜면, 이미 저장된 입력값·추가·삭제·이력을 새 키로 옮깁니다(옮기기 전 백업이 먼저 남음). 옛 키나 새 키가 두 행 이상에 해당하면 그 기록은 옮기지 않고 창에 건수를 알립니다.
- 입력값이 있으면 원본 값보다 우선합니다. 원본과 다른 칸은 표에서 왼쪽 색 띠로 표시되고, 마우스를 올리면 원본 값과 입력자가 보입니다.
- **[저장] 방식**: 칸 입력·행 추가·삭제·되살리기는 [저장] 을 누르기 전까지 내 화면(이 PC 브라우저)에만 있습니다. 노란 칸 = 저장 전 입력, 초록 줄 = 추가 예정, 취소선 줄 = 삭제 예정. 저장 전 변경은 브라우저를 새로 고쳐도 남고, 창을 닫으려 하면 경고합니다. Ctrl+S 로도 저장합니다.
- [저장] 은 변경 전부를 한 번에 보내고, 서버는 **전부 반영하거나 하나도 반영하지 않습니다.** 반영되면 다른 PC 화면은 `poll_seconds`(기본 10초) 안에 바뀝니다.
- 다른 사람이 먼저 저장한 칸을 내가 바꿨다면 저장할 때 목록 창이 뜹니다: 취소 / 겹친 칸은 저장된 값으로 두고 나머지 저장 / 모두 내 값으로 덮어쓰기. 저장 전에도 그런 칸은 빨간 테두리로 미리 보입니다.
- 행 추가: Test(기본 EM), List_no·Process 필수, Total수량을 비우면 DUT × 16. 같은 Test+List_no 가 이미 있으면 막습니다.
- 행 삭제는 지우지 않고 "삭제 표시"만 합니다. 표 아래 "삭제된 행" 에서 되살릴 수 있고, 내보내기 .txt 에서는 빠집니다.
- 날짜는 2026-11-27, 2026/11/27, 2026.11.27 을 받아 2026-11-27 로 통일합니다. 쉼표는 전각 `，`로 바꿉니다.
- 모든 입력은 이름·PC IP·시각과 함께 `history` 에 남고 "변경 이력" 탭에서 봅니다.
- 서버를 켤 때마다 `data/backups/overlay_YYYYMMDD.db` 스냅샷(최근 14개)을 남깁니다. **백업 대상은 overlay.db 하나**입니다.
- "입력값 합친 .txt" 는 원본과 같은 17컬럼 형식(빈 값 `.`)으로 내려받는 파일입니다. 원본 파일은 바꾸지 않습니다.

## API (쓰기는 POST `/api/save`, `/api/edit` 둘, 나머지 쓰기 요청은 405)

| 경로 | 내용 |
| --- | --- |
| `GET /api/status` | revision, 행 수, 격리 수, 원본 연결 오류 |
| `GET /api/data` | 원본+입력값을 합친 행(`rows`), 삭제된 행(`deleted`), 격리 줄, 메타, 설정 |
| `POST /api/save` | `{user, ops:[{op:set,key,field,value,version} / {op:add,row} / {op:delete,key} / {op:restore,key}]}` → 200 / 409(`conflicts` 목록, 아무것도 저장 안 함) / 400·404(`error`, 문제 된 `i`). 한 번에 500건까지 |
| `POST /api/edit` | 칸 하나 저장 (이전 버전 호환) |
| `GET /api/history` | 최근 입력 이력 300건 |
| `GET /api/export/txt` | 입력값을 합친 원본 형식 .txt 다운로드 |

## 운영 메모

- 원본이 바뀌면 서버가 다음 조회 때 다시 읽고, 화면은 `poll_seconds`(기본 10초)마다 확인해 자동 갱신합니다.
- 원본 파일에 접근하지 못해도 서버는 멈추지 않고 마지막 데이터를 보여주며 상단에 오류를 표시합니다.
- 설비별 Oven 대수는 기본으로 비어 있습니다. 미리보기의 설비명(MO-01~05)과 대수(24/24/16/12/5)는 가정값입니다.
- 관리자 PIN, Back-end Test(뒤로 미룸), exe 빌드는 아직 없습니다.
- `overlay.db` 는 서버 PC 로컬 디스크에 두세요. 공유 폴더 위 SQLite 는 잠금이 불안정합니다.
